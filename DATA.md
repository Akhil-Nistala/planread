# Data, models and licences

Nothing in this table is committed to git; every item is downloaded or regenerated by a script.

## Pretrained models (`scripts/download_models.py`, SHA256-pinned)

| File | Source | Licence | Use |
|---|---|---|---|
| `det_v6_small.onnx` | PaddleOCR PP-OCRv6 det (small), ONNX export from the RapidOCR model zoo v3.10.0 (modelscope.cn/RapidAI/RapidOCR) | Apache-2.0 | text-line detection (DBNet) inside crops |
| `rec_v6_small.onnx` | PaddleOCR PP-OCRv6 rec (small), multilingual incl. Japanese; 18,708-char dictionary embedded in ONNX metadata | Apache-2.0 | default recogniser |
| `rec_japan_v4_mobile.onnx` | PaddleOCR PP-OCRv4 mobile Japanese rec; 4,399-char dictionary | Apache-2.0 | alternative recogniser |

Neither pretrained dictionary contains `㎡`; the Japanese v4 dictionary also lacks `±`.
These show up as out-of-charset characters in `EVALUATION.md`.

## Synthetic data (`data/`, regenerated from seeds in `configs/synth.yaml`)

| Set | Command | Size (default) |
|---|---|---|
| Recognition lines (`rec/{train,val,test_clean,test_hard}`) | `python -m data_gen.make_datasets --what rec` | 40,000 / 2,000 / 2,000 / 2,000 |
| Orientation crops (`orient/{train,test}`) | `--what orient` | 12,000 / 1,500 (5 balanced classes) |
| Detection blocks, PaddleOCR det label format (`det/{train,test}`) | `--what det` | 2,000 / 200 |
| Scanned sheets + PlanScope JSON + GT (`docs/`) | `python -m data_gen.make_docs` | 12 sheets, 300 DPI A3 |

Text comes only from `configs/vocab.yaml` (materials, rooms, notes; shared with PlanScope)
plus generated strings (`data_gen/text_sources.py`): product- and manufacturer-*like* names
assembled from random katakana syllables and series codes (**no real brand names**),
dimensions (`t=12.5`, `φ100`, `600×600`, `@455`, `±0`, `18.6㎡` ...), note fragments and
random runs over the charset so rare kanji are seen during training.

`test_hard` is generated with at least one crossing line (dimension/leader/grid/wall line)
plus forced blur, noise and JPEG; `test_clean` has no augmentation at all.

## Fonts

The sampler uses the first available fonts listed in `configs/synth.yaml`.

* **This repo's numbers were produced with Windows system fonts** (Yu Gothic R/M/B/L, MS
  Gothic family; Arial, Times New Roman, Calibri, Consolas, Verdana for pure-ASCII strings).
  They are used locally to *render* training images and are not redistributed.
  No Mincho/serif Japanese font was available, which is a real gap: many drawings use Mincho.
* On Linux/Colab, `apt-get install fonts-noto-cjk` adds Noto Sans CJK JP and Noto Serif CJK JP
  (SIL OFL 1.1), which the config picks up first.

## Charset (`charset/charset.txt`, 3,434 chars, `python -m src.charset build`)

Vocabulary characters, JIS X 0208 Level-1 kanji (2,965; derived offline from Python's
EUC-JP codec, which covers almost all Jōyō kanji), hiragana, katakana, full- and half-width
ASCII, CJK punctuation and drawing symbols (`φ × ± @ ㎡ ℃ ① ㈱ ...`).

## Real data

None. All evaluation is on synthetic data, and PlanScope's trained detector does not exist yet
(its Milestone 3), so end-to-end evaluation uses oracle regions produced by the sheet generator.
