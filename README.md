# PlanRead — Rotated, Bilingual (Japanese + English) OCR for Building Drawings

Second stage of an asbestos-containing-material (ACM) screening pipeline:

```
drawing ─► PlanScope ─────────► JSON v1.0 ─► PlanRead (this repo) ─► JSON v1.1 ─► ACM matching
           layout & tables:                    fills every needs_ocr       text + calibrated conf
           regions + cells,                    region / cell               + top-5 alternatives
           text_source = vector | needs_ocr
```

PlanRead reads every region and table cell that PlanScope marked `needs_ocr` and writes the
text back **without breaking PlanScope's contract**: the output schema v1.1 is generated from
PlanScope's vendored v1.0 schema by purely additive changes (`text_source: "ocr"`, `ocr_conf`,
`ocr_orientation`, `ocr_lines[].alternatives`), and every v1.0 document is still valid v1.1.
It never decides whether anything contains asbestos; it reports how sure it is so the downstream
matcher can route low-confidence readings to "needs review".

## Pipeline

```
region polygon / cell bbox
  │  crop + perspective rectification (homography kept to map lines back to page px)
  ▼
orientation classifier (CNN, 5 classes: 0 / 90 / 180 / 270 / 縦書き vertical)
  │  low confidence → top-2 orientations re-scored by the recogniser
  │  vertical → glyphs split by row-ink profile and re-flowed into a horizontal line
  ▼
line detection: DBNet (PP-OCRv6 det) for multi-line crops; cells/one-line crops skip it
  │  reading order: rows by vertical overlap, then left→right
  ▼
recognition (CTC): PP-OCRv6 (default) | PP-OCRv4-japan | CRNN trained here
  │  prefix beam search → top-5 alternatives with relative probabilities
  ▼
confidence calibration: logistic regression on decoding features → P(line exactly right)
  ▼
JSON v1.1 (text, ocr_conf, ocr_lines[polygon, conf, raw_conf, alternatives], flags)
  + table headers filled and mapped to canonical fields (室名→room, 床→floor, 幅木/巾木→baseboard …)
```

## Quick start

Windows PowerShell (one command per line):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install torch==2.15.0 --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
python scripts/download_models.py           # pinned, SHA256-checked PP-OCR ONNX models
python -m src.charset build                 # charset/charset.txt
python -m data_gen.make_datasets            # synthetic rec / orientation / detection sets
python -m data_gen.make_docs                # 12 scanned sheets + PlanScope JSON + GT
python -m src.orientation train             # ~minutes on CPU
python -m src.crnn train                    # optional in-repo recogniser (slow on CPU)
python -m eval.evaluate_rec                 # + fits calibrators
python -m eval.evaluate_det
python -m eval.evaluate_docs
pytest
streamlit run app.py                        # demo site
```

Run on PlanScope output:

```bash
python -m src.pipeline --layout-json drawing.json --source drawing.pdf --out drawing.ocr.json
```

PDFs are re-rendered at each page's `dpi` with PyMuPDF (exactly as PlanScope renders them),
and the image size is checked against the JSON's `width`/`height` before cropping.

## Output contract (v1.1)

`contracts/schema_v1.1.json` is generated by `python -m src.schema` from
`contracts/planscope_schema_v1.0.json` (copied from planscope@fc8cd0a);
`tests/test_contract.py` checks that the extension is additive and that the committed
file is up to date. On every OCR'd region/cell:

| field | meaning |
|---|---|
| `text` | lines joined with `\n`, width-folded (Ｔ１２→T12; symbols like ㎡ φ ± kept) |
| `text_source` | `"ocr"` |
| `ocr_conf` | calibrated confidence, **min over the item's lines** (an item is only as good as its worst line) |
| `ocr_orientation` | `0 / 90 / 180 / 270 / vertical` |
| `ocr_lines[]` | per line: `text`, `polygon` (page px), `conf` (calibrated), `raw_conf`, `alternatives` (top-5 `{text, score}`) |
| `ocr_flags` | `vertical_split`, `orientation_rescored`, `low_conf` (<0.5), `empty`, `text_from_cells` |

Tables: each cell is OCR'd separately (long table rules are removed from cell crops first);
the table region's own `text` is the cells joined row by row, and `headers` /
`canonical_headers` are filled from the header row when A left them null.

## How it feeds asbestos-material matching

* Match against the material database using `text` **and** every entry of `alternatives`;
  a top-1 miss is often a top-5 hit (see top-5 recall).
* Use `ocr_conf` as the gate for "needs review". It is calibrated on synthetic validation
  data, so treat it as *relative* on real scans until it has been recalibrated on real data.
* `canonical_headers` tells C which column a material came from (floor / wall / ceiling …).
